A program (Node 22, no dependencies) that writes one comment a developer
left above fragile production code to `/output/entry.txt` — a function that
returns the right answer for the wrong reason, and the warning that both of
its bugs are load-bearing.

## The line

> This function returns the right answer for the wrong reason. Both bugs are load-bearing.

88 characters, 88 bytes, no trailing newline.

## Why this line wins against the judge brief

The judge weighs, most important first: a funny comment about fragile
legacy code, the kind a real developer would leave above code they are
afraid to touch; honesty that stings, naming a real, recognisable failure;
economy, with the turn landing on the last few words; a fresh angle, not
the usual off-by-one, who-wrote-this or no-comments cliche; and a voice
that reads like a comment actually left in a codebase.

- **Really about fragile code.** A function whose correct output depends
  on two bugs cancelling each other out is exactly the code nobody dares
  touch.
- **A sting, not an observation.** It names the precise failure: the
  answer is right for the wrong reason. "Load-bearing" is both the joke
  and a genuine engineering warning, and it lands on the last words.
- **Fresh image.** "Load-bearing bugs" is a construction metaphor, not a
  dev-joke stock phrase — no off-by-one, no who-wrote-this, no
  don't-touch, no works-on-my-machine.
- **Tight.** 88 characters, two sentences, no wasted words, no second
  joke crowding the first.
